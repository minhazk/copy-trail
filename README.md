# Copy Trail

A small native macOS clipboard history app built with Swift, SwiftUI, and AppKit.
Open the picker from the menu bar or with **⌘⇧V**, search recent copies, then press
Return to copy a selected item. Your previous app regains focus; use **⌘V** to paste.

## First version

- Text and links copied while the app is running, newest first.
- Search, arrow-key navigation, Return to copy, and Escape to dismiss.
- 100 unique entries, with repeated copies moved to the top.
- Pause/resume, delete individual entries, and clear history.
- Session-only storage: no database, files, analytics, or network service.
- Best-effort exclusion of concealed, transient, autogenerated, and remote-marked data.
- A menu bar fallback if another app already owns the shortcut.

Requires **macOS 14+** and **Swift 5.9+**. Linux is a source editing host; the macOS
UI must be built and run on a Mac. There are no third-party package dependencies.

## Build and run on a Mac

```sh
swift test
./scripts/build-app.sh
open "dist/Copy Trail.app"
```

On a workstation with the resource queue installed, run finite jobs through it:

```sh
~/.local/bin/resource-run --kind build -- swift test
~/.local/bin/resource-run --kind build -- ./scripts/build-app.sh
open "dist/Copy Trail.app"
```

For a single build-and-launch command, use `./script/build_and_run.sh` on the Mac
(or add `--verify` to check the launched process). This entrypoint automatically
uses the workstation resource queue when installed.

The script creates a development app bundle with an ad-hoc signature. It is not
notarized or ready for public distribution. You can also open `Package.swift` in
Xcode. The app has no Dock icon; quit it through the picker's more-options menu.

## Clipboard and Universal Clipboard

Monitoring checks the pasteboard change counter every 750 ms. It reads text only
after a change and never writes during recording, searching, clearing, or deleting
history. The clipboard already present at launch is not imported. Very rapid
copies between polls can be missed; this is not an exhaustive system copy log.

Choosing a history item explicitly replaces the current clipboard with plain
text. macOS can then share that new copy through Universal Clipboard as usual.
History itself is local and does not sync. Items marked
`com.apple.is-remote-clipboard` are skipped before reading their text, to avoid
proactively retrieving another device's content. That marker is a best-effort
convention, not a public compatibility guarantee. Real Mac/iPhone testing remains
necessary to verify Handoff behavior and transfer latency across OS versions.

macOS may ask for clipboard access depending on its version and privacy settings.
Allow access if you want background recording. Automatic pasting into other apps
is not implemented, so this version does not request Accessibility permission.

Sensitive-type filtering is also best effort: unmarked passwords or other secrets
can still enter history. Pause recording when appropriate. Each entry is limited
to 1 MB of UTF-8 text, and only 100 entries are retained. Images, files, and rich
text formatting are not supported in this first version.

## Layout

- `Sources/CopyTrail`: menu bar app, global shortcut, picker, pasteboard adapter.
- `Sources/CopyTrailCore`: clipboard history and capture policy with an injected clipboard.
- `Tests/CopyTrailCoreTests`: recording, privacy markers, deduplication, limits,
  search, pause/resume, clear, and restore behavior.
- `scripts/build-app.sh`: development `.app` bundle builder.

## Manual acceptance checks

1. Start the app and copy two different strings in another app.
2. Open with ⌘⇧V; search, navigate with arrows, and press Return.
3. Verify the previous app is focused and ⌘V pastes the selected string.
4. Pause, copy another string, resume: the paused copy should not appear.
5. Clear history: the current system clipboard must still paste normally.
6. Quit and relaunch: history should be empty.
7. Copy from iPhone to Mac and Mac to iPhone with Handoff enabled, with Copy Trail
   running and paused; check for transfer delays and unexpected prompts.
8. Check denied clipboard access, shortcut conflicts, multiple Spaces, and full-screen apps.

Next steps: image history, configurable shortcuts/limits, optional automatic paste,
login launch, and a signed/notarized release. End-to-end UI and cross-device checks
must be completed before calling the app release-ready.
